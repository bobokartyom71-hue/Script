# Script

Python-скрипт для массового подключения к сетевым устройствам из NetBox (Cisco IOS, Huawei VRP, MikroTik RouterOS), сбора данных и применения конфигурации по шаблонам.

## Что делает

- Загружает список устройств из NetBox по фильтрам (регион, группа сайтов, роль, статус active).
- Поддерживает фильтрацию по:
  - списку IP-адресов (`hostsfile`),
  - списку номеров объектов/АЗС (`hostsnumbers`). Требуется когда на вход поутупают список с номерами АЗС, без IP. Скрипт на основе номеров стягивает IP из NetBox.
- Подключается по SSH параллельно (многопоточно).
- Выполняет `show`-команды, парсит результат и генерирует конфигурацию из шаблонов.
- Применяет конфиг на устройствах и сохраняет его (кроме некоторых сценариев).
- Поддерживает отдельный режим работы с VTY ACL (`--vty`). Требуется когда нужно редактировать только ACL который привзян к VTY. Где-то он standard, где-то extended, где-то VTY_ACL, где-то VTY-ACL...
- Поддерживает тестовый запуск без применения конфигурации (`--test`). Скрипт выведет результат парсинга и сгенерированных команд в консоль.

## Структура проекта

- `main_runner.py` — основной исполняемый скрипт (логика подключения, обработки и запуска по платформам).
- `commands.py` — словарь команд и шаблонов конфигурации для каждой платформы.
- `pynetbox_class.py` — работа с NetBox и парсинг CLI-аргументов.
- `requirements.txt` — зависимости Python.
- `hostsfile` — пример файла со списком IP (по одному в строке).
- `hostsnumbers` — пример файла со списком номеров объектов/АЗС.
- 
Установите зависимости:

```bash
pip install -r requirements.txt
```

## Настройка

Скрипт читает переменные окружения из `.env` (через `python-dotenv`):

```env
NETBOX_URL=https://your-netbox.example.com
NETBOX_TOKEN=your_token
```

> Если `NETBOX_URL` или `NETBOX_TOKEN` не заданы, скрипт завершится с ошибкой.

## Запуск

Базовый запуск:

```bash
python main_runner.py [опции]
```

При обычном запуске скрипт попросит:

- `Username`
- `Password`

### Основные аргументы

#### Группы объектов

- `-c`, `--coco` — сервисные АЗС COCO
- `-p`, `--copo` — партнерские АЗС COPO/CODO
- `-r`, `--coro` — партнерские АЗС CORO
- `-P`, `--PNPO` — объекты ПНПО
- `-n`, `--neft` — нефтебазы
- `-o`, `--offices` — офисы

#### Регионы

- `-ru`, `--RU`
- `-kz`, `--KZ`
- `-kg`, `--KG`
- `-by`, `--BY`
- `-tj`, `--TJ`

#### Дополнительные

- `-role`, `--role` — ID роли устройства в NetBox (по умолчанию `1`)
- `-hf`, `--hostsfile` — файл с whitelist IP-адресов
- `-hn`, `--hostsnumbers` — файл с whitelist номеров объектов/АЗС
- `-vty`, `--vty` — режим изменения VTY ACL
- `-f`, `--force` — пропустить этап `show/analyze`, сразу прописать команды в config. Например пачку ntp серверов, т.е. когда нам ничего не нунжно запршивать с устройства. 
- `-t`, `--test` — тестовый режим (печать config в консоль, без применения на устройство)

Применить стандартный сценарий для COCO в регионе RU:

```bash
python main_runner.py --coco --RU
```

Работать только по списку IP из файла:

```bash
python main_runner.py --copo --KZ --hostsfile hostsfile
```

## Логи и результаты

- Основной лог: `result_YYYY-MM-DD_HH-MM-SS.log`
- Ошибки: `errors.log`
- Также создается `netmiko_session.log` для SSH-сессий.

В логи пишутся:

- успешные/ошибочные подключения,
- ошибки парсинга,
- ошибки применения конфигурации,
- итог обработки устройств.
